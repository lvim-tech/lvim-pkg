1. INTRODUCTION                                            *lvim-pkg-intro*

lvim-pkg is the single data + operations hub for the LVIM installable
ecosystem: it answers every "what is available / installed / missing"
question and performs every install / update / remove across three backends.

  Kind       Backend                       Handles ~
  mason      mason-registry                LSP servers, linters, formatters,
                                           DAP, the tree-sitter CLI
  parser     treesitter-parser-registry    treesitter parsers + their queries
  plugin     vim.pack                      Neovim plugins

Both the Mason and the parser backends are self-contained — no mason.nvim and
no nvim-treesitter. Each consumes an editor-agnostic community catalogue and
installs from source itself: Mason via npm / pypi / golang / cargo / github;
parsers by compiling the grammar with the tree-sitter CLI and dropping the
`.so` + query files on the runtimepath, so Neovim's built-in |vim.treesitter|
uses them. Each catalogue is fetched at setup when its on-disk cache is
missing or older than `registry_ttl`, and on demand.

lvim-pkg has no UI (that is lvim-installer) and no editor runtime (LSP attach
lives in lvim-lsp, treesitter highlighting in lvim-ts). Domain plugins depend
on lvim-pkg; lvim-pkg depends on nothing in the ecosystem.

==============================================================================
2. INSTALLATION                                     *lvim-pkg-installation*

No Lua-plugin dependencies — install state is plain JSON under the install
root (see |lvim-pkg-layout|). External tools are needed only to fetch and
build packages: curl, tar/unzip, a C compiler (cc) and the per-source
toolchains (git, npm, python3/pip, go, cargo). See `:checkhealth lvim-pkg`.

Bundled with LVIM IDE (loaded early — other plugins query it during their own
setup).

lvim-installer (recommended) — install / update / pin it from the LVIM package
manager (Plugins tab); it installs through Neovim's built-in |vim.pack|: >vim
  :LvimInstaller plugins
<
Native (vim.pack): >lua
  vim.pack.add({
      { src = "https://github.com/lvim-tech/lvim-pkg" },
  })
  require("lvim-pkg").setup({ ensure_cli = true })
<

3. SETUP & CONFIGURATION                                   *lvim-pkg-setup*

                                                         *lvim-pkg.setup()*
`setup(opts)` merges the given options into the live defaults in place, so
every `require("lvim-pkg.config")` reader sees the effective values. >lua
  require("lvim-pkg").setup({
      root = vim.fn.stdpath("data") .. "/lvim-pkgs",
      ensure_cli = true,    -- install the tree-sitter CLI on setup when missing
      snapshot_dir = nil,   -- snapshot dir (default: <config>/.snapshots)
  })
<
Fields (|LvimPkgConfig|):

  root          string      Unified install root (subfolders packages/ bin/
                            ts/). Default: stdpath("data").."/lvim-pkgs".
  ensure_cli    boolean     Install the tree-sitter CLI on first setup when
                            missing. Default: true.
  snapshot_dir  string|nil  Directory holding the version snapshots and the
                            `active` marker. Default: <config>/.snapshots.
  registry_ttl  integer     Seconds before a cached catalogue is re-fetched at
                            setup. 0 disables the age check. Default 7 days.
  max_concurrency integer   Packages installed in parallel per batch. Default 4.
  extra_parsers table       Tree-sitter parsers the community catalogue does
                            not carry, keyed by language, in the registry's own
                            entry shape. Merged over the fetched catalogue and
                            winning a name collision. Default {}.

                                                  *lvim-pkg-extra-parsers*
A grammar missing from the catalogue is added as one entry rather than by
forking three hundred someone else maintains: >lua

    require("lvim-pkg").setup({
        extra_parsers = {
            org = {
                filetypes = { "org" },
                source = {
                    type = "self_contained",
                    parser_url = "https://github.com/nvim-orgmode/tree-sitter-org",
                },
            },
        },
    })
<
A plugin that needs a grammar can contribute it from its own setup() instead,
so installing that plugin is enough and no central config is edited: >lua

    require("lvim-pkg").register_parser("org", { filetypes = { "org" }, source = { … } })
<
Either way the language becomes installable, updatable and removable like any
catalogue entry. `source.type` is `self_contained` (grammar and queries in one
repository; `queries_dir` names the subdirectory when it is not `queries/`),
`external_queries` (`parser_url` + `queries_url`) or `queries_only` (`url`,
reusing another parser named in `requires`).

==============================================================================
4. LAYOUT ON DISK                                         *lvim-pkg-layout*

Everything lvim-pkg installs lives under `root`:

  packages/         Mason binaries
  bin/              linked executables, added to $PATH
  ts/parser         treesitter parsers   (added to the runtimepath)
  ts/queries        treesitter queries   (added to the runtimepath)
  state.json        install receipts + per-filetype declines (JSON)
  <snapshot>.json   pins / per-plugin + per-Mason version choices
  registry.json     cached Mason catalogue
  ts-registry.json  cached parser catalogue

Neovim plugins are NOT here — |vim.pack| owns them under
`site/pack/core/opt`. Catalogues download at setup when the cache is missing
or older than `registry_ttl` (default 7 days; 0 disables). Force a re-download
with `:LvimInstaller update-registry [mason|ts|all]` (the command lives in
lvim-installer).

5. API                                                       *lvim-pkg-api*

  local pkg = require("lvim-pkg")

------------------------------------------------------------------------------
BACKEND OPERATIONS                                *lvim-pkg-api-operations*

`kind` is one of "mason", "parser", "plugin".

  pkg.available(kind)            string[]
  pkg.installed(kind)            string[]
  pkg.is_installed(kind, name)   boolean
  pkg.install(kind, items, cb, opts)
  pkg.update(kind, names, cb)
  pkg.remove(kind, names, cb)
  pkg.backend(kind)              the backend module, or nil

Argument shapes are backend-specific: Mason and parser take names; plugin
takes |vim.pack| specs.

------------------------------------------------------------------------------
VERSIONS                                            *lvim-pkg-api-versions*

  pkg.installed_version(name)             string|nil (Mason package version)
  pkg.available_versions(kind, name, cb)  async; cb(string[]|nil), Mason only
  pkg.parser_installed_version(lang)      string|nil (grammar revision)
  pkg.is_managed(name)                    installed in our path (has our receipt)
  pkg.package_path(name)                  install dir under our managed root
  pkg.bin_dir()                           managed bin dir (linked exes, on PATH)

------------------------------------------------------------------------------
REQUIREMENT REGISTRY                            *lvim-pkg-api-requirements*

Domain plugins register a provider during their own setup(); the unified
prompt aggregates every provider's missing items for the opened filetype.

  pkg.register_provider(name, fn)   fn(ft) -> LvimPkgItem[]
  pkg.missing_for_ft(ft)            LvimPkgItem[] (missing, not declined)
  pkg.on(event, fn)                 installer events: "installing",
                                    "removing", "removed"
  pkg.emit(event, ...)              fire subscribers

------------------------------------------------------------------------------
PLUGIN INTROSPECTION                                 *lvim-pkg-api-plugins*

Reported by the host loader.

  pkg.register_plugins(map)              host registers the full spec set once
  pkg.record_load(name, reason, time)    host records each load
  pkg.plugins()                          rich info for every plugin
  pkg.plugin_info(name)                  rich info for one
  pkg.plugin_stats()                     { loaded, total }
  pkg.check_outdated(cb, on_progress)    async: plugins with an update
  pkg.parser_outdated(lang)              last-check result for a parser
  pkg.check_parsers_outdated(cb, on_progress)

Plugin git data (the pin menu): >lua
  pkg.plugin_branches(name) / plugin_default_branch(name) / plugin_current(name)
  pkg.plugin_tags(name) / plugin_commits(name, ref) / plugin_newest_tag(name)
  pkg.plugin_resolve_tag(name, prefix) / plugin_branch_tip(name, branch)
  pkg.plugin_fetch(name, cb) / plugin_checkout(name, ref)
  pkg.plugin_update_branch(name, branch)
  pkg.load_tags(cb) / git_log(name) / load_git_log(name, cb)
<
The host's pack loader also calls two submodules directly (not proxied through
`pkg.*`): `require("lvim-pkg.loader")` for the introspection store above, and
`require("lvim-pack.deps").resolve(modules)` to expand each spec's
`dependencies` into flat module entries (|vim.pack| does not auto-install
dependencies) before installing.

------------------------------------------------------------------------------
VERSION PINS                                            *lvim-pkg-api-pins*

Per kind; a git ref for plugins. `reftype` is "tag" or "branch"; `branch` is
the branch context for a commit/tag.

  pkg.pin(kind, name, version, reftype, branch)
  pkg.get_pin(kind, name)        string|nil
  pkg.get_pin_full(kind, name)   { version, reftype, branch }|nil
  pkg.pins()                     kind -> name -> version
  pkg.pins_full(kind)            name -> full record
  pkg.unpin(kind, name)

------------------------------------------------------------------------------
SNAPSHOTS                                          *lvim-pkg-api-snapshots*

A snapshot pins the whole installed set (each plugin's git HEAD, each Mason
package's version) to a named file; selecting one and restoring its diff
checks out / reinstalls only what differs.

  pkg.snapshots()                string[]
  pkg.active_snapshot()          string
  pkg.select_snapshot(name)      boolean
  pkg.snapshot_save(name)        ok, err?
  pkg.snapshot_diff()            { plugins = {...}, mason = {...} }
  pkg.snapshot_restore(diff, cb, on_progress)
  pkg.snapshot_export(dest)      write the active set to a shareable lockfile
  pkg.snapshot_import(src, name) read a lockfile into a new (non-active) snapshot

------------------------------------------------------------------------------
DECLINES                                            *lvim-pkg-api-declines*

Per-filetype "do not offer these again". missing_for_ft filters these out and
the prompt stops offering them.

  pkg.decline(ft, names)         names: string[]
  pkg.undecline(ft, name)        re-enable one
  pkg.declined()                 { { ft = "...", name = "..." }, ... }

------------------------------------------------------------------------------
REGISTRY REFRESH                                    *lvim-pkg-api-registry*

  pkg.update_registry(which, cb, force)

`which` is "mason", "ts" or "all" (default "all"); `force` ignores the cache
and re-downloads now.

==============================================================================
6. TYPES                                                   *lvim-pkg-types*

                                                            *LvimPkgItem*
  { kind = "mason"|"parser"|"plugin", name = "...", label? = "...",
    group? = "..." }

A domain plugin registers a provider during its own setup(): >lua
  require("lvim-pkg").register_provider("ts", function(ft)
      local lang = require("lvim-ts").missing_for_ft(ft)
      return lang
          and { { kind = "parser", name = lang, label = "parser: " .. lang } }
          or {}
  end)
<
